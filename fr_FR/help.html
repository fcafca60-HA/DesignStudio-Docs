QuickStart — Installer et importer le Dashboard Jeedom

Pour démarrer sans créer les tuiles une à une, utilisez l'assistant d'import complet. Ce guide correspond au mode d'installation File de Design Studio 0.90.34-beta.

1. Installer depuis un fichier ZIP

Dans Jeedom, ouvrez Plugins → Gestion des plugins → Ajouter un plugin. Sélectionnez Type de source : Fichier, indiquez l'ID logique designstudio, puis Envoyer un plugin et choisissez l'archive ZIP complète. Cliquez sur Sauvegarder. L'avertissement sur les plugins hors Market est un message standard de Jeedom.

2. Activer et configurer

Ouvrez Plugins → Gestion des plugins → Jeedom Design Studio, activez le plugin, puis contrôlez son état. Le plugin est prévu sans démon ni dépendances système obligatoires. Pour une archive File contenant les sources et si le frontend n'est pas déjà compilé, exécutez le script build_frontend.sh depuis le répertoire du plugin.

3. Régler les accès

Dans la configuration du plugin, section Utilisateurs, droits et Kiosque, vérifiez le profil Design Studio des utilisateurs et les pages autorisées. Pour le premier import, utilisez un compte administrateur Jeedom. Les autorisations natives Jeedom restent prioritaires.

4. Ouvrir la conception

Suivez Plugins → Organisation → Jeedom Design Studio puis cliquez sur + Jeedom → Importer TOUT le Dashboard Jeedom.

5. Vérifier les propositions

L'assistant analyse les équipements et propose une tuile par équipement reconnu. Utilisez À vérifier pour contrôler les détections incertaines. Les équipements masqués ou désactivés peuvent être exclus. Attention : « Créer le Dashboard validé » remplace le projet courant ; faites une sauvegarde JSON avant de confirmer.

6. Enregistrer et tester

Cliquez sur Créer le Dashboard validé après vérification, puis Enregistrer Jeedom. Ouvrez Dashboard et testez les valeurs, commandes, pages et l'affichage sur smartphone. En cas de commande absente ou erronée, utilisez les propriétés de la tuile puis Données → Affecter toutes les commandes.

Précaution : pour une installation déjà personnalisée, exportez d'abord votre projet avec Backup PC. N'utilisez pas l'import complet sur un projet à conserver sans cette sauvegarde.

Une version PDF illustrée est également incluse dans le plugin : docs/fr_FR/QuickStart_DesignStudio.pdf.

Démarrage rapide

1. Ajouter une tuile

Ouvrez Widgets, choisissez une famille puis déposez ou ajoutez la tuile sur la page.

2. Affecter ses données

Dans Données, utilisez Affecter toutes les commandes…. Le tableau permet de programmer les données en série.

3. Régler son apparence

Visibilité masque les éléments inutiles. Style règle format, animation, historique et options propres à la tuile.

Conseil : affectez d’abord une commande de l’équipement principal. Le sélecteur reste ensuite sur le même équipement Jeedom pour programmer les autres données beaucoup plus vite.

Une tuile sélectionnée expose quatre onglets principaux.

Les options proposées s’adaptent au type de tuile : une lumière, un thermostat ou un Résumé Énergie n’ont pas les mêmes paramètres.

Pages

Les onglets de pages servent à répartir le Dashboard. Une page peut disposer de son propre thème et de règles d’alerte. L’onglet peut être animé lorsqu’une condition d’alerte est vraie.

Déplacement / redimensionnement

En Conception Desktop, les tuiles utilisent la grille. Sur smartphone, Design Studio applique une disposition responsive séparée : le réordonnancement tactile ne modifie jamais les coordonnées Desktop.

Affectation des données Jeedom

L’onglet Données possède un mode d’affectation groupée. C’est le moyen recommandé pour programmer une tuile.

Affectation groupée

  • Cliquez sur Affecter toutes les commandes….
  • Chaque ligne correspond à une donnée Design Studio.
  • Sélectionnez la commande Jeedom associée.
  • La valeur actuelle aide à vérifier immédiatement l’affectation.
  • Les commandes INFO/ACTION sont filtrées selon le besoin.

Même équipement automatiquement

Après avoir choisi par exemple ozbJulie.temperature, le sélecteur reste sur l’équipement ozbJulie. Les commandes humidité, batterie, LQI… sont donc directement disponibles pour les lignes suivantes.

Auto-détection

Auto-détecter les données non affectées utilise nom, unité, type, logicalId et genericType. Les affectations déjà existantes ne sont pas remplacées.

Options avancées

L’affectation individuelle reste disponible pour les réglages fins : inversion booléenne, décimales, options particulières ou commandes atypiques.

Une donnée affichée comme « — » indique généralement qu’aucune commande n’est liée, que la commande n’a pas de valeur ou que la valeur n’est pas disponible.
🕘

Historique des valeurs

Principe global

Toute commande INFO historisée dans Jeedom peut être consultée depuis une tuile. Les valeurs cliquables ouvrent l’analyse historique quand l’association le permet.

Accès global d’une tuile

L’icône historique de la tuile permet d’accéder aux séries INFO disponibles sans devoir connaître à l’avance la commande.

Valeurs calculées

Quand une valeur est calculée, Design Studio ouvre les historiques des sources utilisées. Exemple : Maison calculée dans Résumé Énergie peut renvoyer vers PV, réseau et batterie.

Pas de données ?

Vérifiez que la commande est bien cochée Historiser dans Jeedom et qu’elle possède déjà des points sur la période demandée.

Visibilité, formats et animations

Visibilité

Chaque tuile peut masquer ses éléments utiles : titre, icône, état, batterie, humidité, valeur, unité, boutons, LIVE, etc. Les anciennes tuiles restent visibles par défaut.

Format

Standard, Compact, Mini et autres variantes permettent d’adapter l’information à la place disponible. Certaines tuiles possèdent aussi un comportement responsive interne.

Animation d’état

Selon la tuile : automatique, halo, pulsation, icône animée ou clignotement doux. Les animations n’altèrent pas la valeur Jeedom.

Contacts et informations booléennes

Inverser un contact

Pour toute information binaire reconnue, activez Inverser l’information booléenne lorsque le capteur retourne l’état opposé à la réalité (NF/NO par exemple).

L’inversion concerne le texte, l’icône, les couleurs et l’animation de Design Studio ; elle ne modifie jamais la commande Jeedom.

Aspect visuel

La tuile Ouverture propose notamment : Classique, Porte animée, Fenêtre animée, Contact magnétique, LED, Halo et Minimaliste. Le texte Ouvert/Fermé peut être masqué dans Visibilité.

Linky / LiXee ZLinky TIC

Énergie

Tuile animée avec flux Réseau ↔ Maison, couleurs et vitesse proportionnelles à la puissance. Modes Mini, Standard et Expert.

Données : Puissance soutirée · Puissance injectée (optionnelle) · Intensité · Tension · Fréquence · Index total · Index HC · Index HP · Tarif · Dernière communication

Assistant ZLinky : dans l’onglet Données, le bouton Auto-configurer ZLinky TIC analyse d’abord les commandes réellement alimentées. En TIC Historique, il privilégie PAPP, IINST, HCHC, HCHP, PTEC, ISOUSC et BASE. En TIC Standard, il privilégie SINSTS/SINSTI, IRMS1, URMS1, EAST, EASF01/EASF02, LTARF/NTARF. Les commandes nulles ou indisponibles ne servent pas à choisir le profil.

Flux : en Standard, si SINSTS et SINSTI existent, Design Studio calcule automatiquement le sens net. En Historique, sans puissance d’injection dédiée, aucun faux flux d’injection n’est affiché. Le flux est rafraîchi en continu depuis le cache Jeedom : orange/rouge pour Réseau → Maison, vert pour Maison → Réseau, neutre pour un flux nul. Si ISOUSC est disponible, la jauge est calibrée automatiquement à partir de l’intensité souscrite. Les commandes Jeedom ne sont jamais modifiées.

Style : présentation automatique/Mini/Standard/Expert, puissance maximale de jauge, inversion du sens import/injection et zone neutre autour de 0 W. Tous les blocs peuvent être affichés ou masqués dans Visibilité.

Conseils pratiques

Une tuile = un équipement principal

Quand c’est possible, utilisez les commandes d’un même équipement Jeedom. L’affectation groupée est optimisée pour ce cas.

Masquer ce qui ne sert pas

Sur les petites cartes, retirez libellés et données secondaires pour laisser la priorité à la valeur utile.

Historiser les bonnes commandes

Pour les analyses temporelles, activez l’historisation Jeedom des valeurs importantes avant d’en avoir besoin.

Tester les signes énergie

Vérifiez import/export et charge/décharge. Utilisez les inversions de signe lorsque le fabricant emploie une convention opposée.

Booléens

Un contact NF/NO inversé doit être corrigé dans Design Studio plutôt que de changer le capteur Jeedom si celui-ci est utilisé ailleurs.

Backup avant gros changement

Utilisez Backup PC avant une migration importante de page ou d’équipements.

🧰 Tuile Équipement : commandes ACTION

Pour une tuile Équipement, chaque bouton Exécuter lance la commande ACTION Jeedom correspondante. Design Studio demande directement à Jeedom d’exécuter la commande ; si elle provient du plugin Script, c’est Jeedom qui lance le script configuré. Design Studio n’exécute jamais directement un fichier shell.

Astuce : si une action fonctionne avec le bouton Tester dans Jeedom, le bouton Exécuter de la tuile Équipement doit produire le même effet, sous réserve des droits Jeedom, des permissions Kiosque et d’un éventuel PIN.

🧾 Journal du plugin

Design Studio utilise le journal natif Jeedom designstudio. Le niveau de détail se règle dans la configuration du plugin, rubrique Logs et surveillance. En mode normal, seules les informations importantes et les erreurs sont consignées ; les exécutions de commandes ACTION ne sont détaillées qu’au niveau Debug afin de ne pas surcharger le disque.

💾 Sauvegarde automatique

Depuis la version 0.90.2-beta, Design Studio n’enregistre le projet que lorsqu’une modification réelle de conception est détectée (position, taille, affectation, visibilité, style, page, alerte, etc.). Les changements de température, puissance, batterie, LQI, historiques, logs et autres valeurs temps réel ne déclenchent jamais de sauvegarde. Après une modification, Design Studio attend environ 1,5 seconde après le dernier changement puis effectue une seule sauvegarde. Le bouton Enregistrer Jeedom force toujours une sauvegarde immédiate.

🧾 Journalisation Jeedom

Design Studio utilise le journal natif designstudio. Depuis la version 0.90.2-beta, ce fichier est créé explicitement afin d'apparaître immédiatement dans Configuration du plugin → Logs et surveillance, même si les niveaux Info/Debug sont filtrés. Les commandes ACTION déclenchées depuis Design Studio sont tracées : demande en Debug, succès en Info, erreur en Warning/Error. Les rafraîchissements périodiques ne sont pas journalisés afin d’éviter le spam.

📱 Conception Mobile

Depuis la 0.90.10-beta, la page Conception sur smartphone utilise la même disposition responsive que le Dashboard. Les coordonnées Desktop ne sont jamais modifiées. Vous pouvez réordonner les tuiles au doigt ; Design Studio mémorise uniquement leur ordre mobile. La largeur mobile se choisit dans Style → Disposition smartphone : Auto, Demi largeur ou Pleine largeur. Le menu ⋮ regroupe les commandes secondaires afin de conserver une barre supérieure compacte. Les boutons Widgets et Propriétés ouvrent des tiroirs adaptés au tactile.

💾 Autosauvegarde

Depuis la 0.90.9-beta, les valeurs LIVE Jeedom (températures, puissances, batterie/LQI, historiques, logs, états dynamiques…) sont séparées de la configuration persistante. Une simple mise à jour de valeur ne déclenche donc pas de sauvegarde. Une seule sauvegarde peut être active à la fois par onglet. Si un autre onglet ou utilisateur modifie réellement le projet, la protection de révision refuse l’écrasement et demande de recharger Design Studio.

📱 Smartphone — hauteur compacte 0.90.14-beta

La 0.90.12 supprimait les coupures en agrandissant automatiquement les cellules, mais une hauteur devenue trop grande ne pouvait plus redescendre. La 0.90.13 corrige ce point : Design Studio repart du profil mobile compact, mesure uniquement le contenu utile des cartes riches et peut maintenant agrandir ou réduire la cellule. Les trous verticaux sont compactés automatiquement. Les coordonnées et dimensions Desktop ne sont jamais modifiées.

📱 Smartphone — hauteur dynamique 0.90.12-beta

À 100 %, certaines tuiles riches pouvaient dépasser la hauteur fixe attribuée par la grille mobile et paraître tronquées ou masquées. Design Studio mesure désormais leur contenu réel après affichage et agrandit automatiquement la cellule mobile si nécessaire. Désactivé par défaut, ce réglage n'altère pas les seuils historiques PowerMeter. Choisir la valeur principale ou une commande INFO numérique associée. Les bornes sont inclusives et doivent être strictement croissantes ; la dernière plage n'a pas de limite supérieure. En absence de valeur exploitable, les couleurs habituelles sont conservées. Aucun scénario ni commande Jeedom n'est exécuté. Pour afficher ce rendu sur le site distant PHP, reconstruire et déployer le frontend React puis republier la configuration.

V0.90.58 File - Camera officielle Jeedom (lecture seule)

Prérequis : installer/activer le plugin Camera officiel et configurer un équipement caméra en mode snapshot JPEG. Dans Design Studio : + Jeedom > Équipements, choisir la caméra du plugin officiel, puis Type de tuile : Caméra. Pour une tuile Camera déjà créée, sélectionner la caméra dans Propriétés > Style > Camera officielle Jeedom.

Choisir l'actualisation (Manuel, 5, 10, 30 ou 60 secondes) et le cadrage (Contenir ou Remplir). Cliquer sur l'image pour l'agrandir ; cliquer sur ↻ pour actualiser manuellement. Le navigateur ne reçoit jamais la clé API ni l'adresse IP de la caméra : un endpoint PHP Design Studio contrôle la session et les droits Jeedom, puis transmet uniquement le JPEG.

Limitations de sécurité : pas de RTSP/FFmpeg, PTZ, caméra via token kiosque, ni images sur le site OVH dans cette première version. Si une caméra est inaccessible, désactivée ou refusée par les droits Jeedom, la tuile présente un message sans contourner Jeedom. Ne pas copier les anciennes URL de snapshot du plugin Camera dans les champs Design Studio.

Installation File : après installation du ZIP, exécuter cd /var/www/html/plugins/designstudio && sudo ./build_frontend.sh puis recharger la page. Cette fonctionnalité doit être validée sur un Jeedom de test avant publication Market.

V0.90.59 File - Correction du catalogue Camera

Correction : les équipements du plugin Camera peuvent avoir zéro commande INFO exposée pour protéger leurs URL et clés de snapshot. Le catalogue React conserve maintenant les équipements natifs eqType_name=camera même avec une liste de commandes vide. Après avoir installé le ZIP et exécuté sudo ./build_frontend.sh, utiliser Connexion Jeedom > Tester et charger, puis + Jeedom > Équipements, rechercher TestCam et choisir Caméra. On peut également sélectionner l'équipement dans Propriétés > Style d'une tuile Camera. Le proxy JPEG sécurisé et l'absence d'images sur OVH restent inchangés. Si la liste reste vide, vérifier le retour fullData et le nom de type d'équipement, sans exposer ses secrets.

Camera officielle - V0.90.62 File

La tuile Camera est générique : les équipements de type Camera sont pilotés par leur ID Jeedom, sans configuration de marque. Les flux HTTP JPEG/MJPEG sont transformés en une image JPEG par le proxy. Les autres sources sont déléguées à getSnapshot() du plugin Camera officiel (RTSP selon sa configuration et les outils disponibles). Le navigateur vérifie le décodage JPEG avant de l'afficher, avec source stable pour éviter les images cassées après rafraîchissement. Les images et identifiants ne sont pas publiés sur OVH. Les erreurs restent consultables sans journaliser les URL privées.
